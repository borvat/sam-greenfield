## ما تغير

- `npm run start:release`: مشرف عمليات Node دون Docker، يستعمل نقاط تشغيل سام
  الأصلية، ويوجه الطلبات عبر منفذ عام واحد. العمليات الداخلية على loopback ومنافذ
  يختارها النظام؛ لا تُفترض إتاحة منفذ ثابت في حاوية Replit.
- العامل لا يتوقف بإغلاق صفحة المعاينة. الإيقاف SIGTERM ينتظر عمله الجاري، ثم
  توجد مهلة وحدّ إيقاف قسري. إعادة تشغيل العمليات محدودة، وليست حلقة لا نهائية.
- جاهزية قاعدة البيانات تُراجع أثناء التشغيل: فشل الاتصال يخفض `/readyz` إلى
  503 ويمنع بدء ACT جديد؛ عودة الاتصال تسبق التعافي والاستئناف.
- مسار التركيب يدعم export غير متزامن وnamespace الخاصة بـCJS/ESM. تحويل
  top-level await كان سبب فشل فعلي في تشغيل وحدة الإنتاج تحت tsx في هذا المستودع.
- شروط قبول صريحة من المالك، اختيارية في المسارات القديمة وإلزامية في غلاف
  الإصدار: تخزن في completion_definition الموجودة دون ترحيل جديد. نجاح verifier
  الحسابي لا يكمل الهدف إن خالف هذا العقد. لا يُتعلم من هذا الهدف قبل اكتماله.
- أخطاء HTTP للمزود تحمل تصنيفاً ورمز حالة فقط؛ نص رد الخطأ لا ينتقل إلى السجلات.
  مخرجات الأبناء محجوبة افتراضياً، مع قائمة ضيقة لرموز التشخيص الآمنة.
- MCP في غلاف الإصدار معطل افتراضياً؛ إن فُوّض لاحقاً يتطلب رمزاً منفصلاً ويعرض
  حالتي الخدمات والاختبارات المنقحتين فقط. لا dispatcher، ولا مستخدمين أو ذاكرة أو
  ملفات أو أدوات تنفيذ.
- تحديث tsx إلى 4.23.15 وesbuild إلى 0.28.2 عالج التنبيه الأمني للاعتماد القديم.

## إعداد الإنتاج الذي لم ينفّذ

استعمل `env.production.example` كعقد، وليس ملف أسرار. القيم الفعلية تدخل عبر
خزنة Replit وواجهة إعدادات النشر فقط بعد قرار مالك منفصل.

1. اختيار Reserved VM لتشغيل دائم، وتحديد المنفذ العام الواحد وأمر
   `npm run start:release`. لم تُعدَّل إعدادات Publish الحالية. لا تستخدم
   أوامر dev؛ حواجزها محفوظة وتمنع تشغيلها كإنتاج.
2. قاعدة مستقلة مثبتة الهوية، schema ودور تطبيق غير مالك/NOBYPASSRLS،
   سياق org/entity وTLS. شرط SAM_DATABASE_TARGET ليس إثبات هوية وحده؛
   يجب مقارنة بصمة الهدف من مصدر مستقل قبل أي عملية على الإنتاج.
3. bundle إنتاج مصرح بقدرات فعلية آمنة ومحدودة. bundle الافتراضي دون
   إعدادات قدرات فارغ ويرفضه عقد سام الأصلي؛ bundle الاختبار ممنوع في
   validateRelease. لا يجوز نشر كتالوج fixtures أو افتراض جاهزية الشركات.
4. رموز production مستقلة للوحة ولـMCP عند الحاجة. وجود SESSION_SECRET
   للتطوير ليس توفيراً لهذين الرمزين. لا إنشاء أو إظهار رموز هنا.
5. لا مفاتيح نموذج أو OAuth تُمرر من الغلاف الابتدائي إلى الأبناء. أي
   إتاحة مستقبلية تستلزم عقد بيانات/قدرات وميزانية صريحة واختبارات مستقلة؛
   وجود اتصال Google سابق لا يجيز مستندات شركات أو كتابة.
6. اختبار restore وmonitoring/alerts والكلفة الفعلية على الهدف المعتمد ثم
   إعادة قبول build ثابت. لا Publisher قبل قرار المالك ونجاح هذه البوابات.
