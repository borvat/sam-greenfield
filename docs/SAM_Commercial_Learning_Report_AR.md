# SAM Commercial Learning & Innovation

مسودة تطوير معزولة — 21 أكتوبر 2026. تعتمد على رأس PR #37 المثبّت `cacc3a0d908223d3ed5d0e394592c5b3714509d7`، وتستهدف فرعه للمراجعة حتى يظهر فرق هذه المرحلة وحدها. لم يُدمج PR #37 أو أي PR آخر، ولم تُعدّل نسخة Render أو إعداداتها أو قاعدة إنتاجها أو خدمات مدفوعة.

## النتيجة التي يثبتها هذا التسليم

كود عامل واختبارات محلية لطبقة تحليل وتعلّم تجاري، مع استرجاع الدروس عبر سياق التخطيط الموجود في PR #37. جميع بيانات QNAN هنا **مصطنعة وموسومة SYNTHETIC**. لا يمثّل أي مبلغ أو منتج أو حساب في الاختبارات وضع QNAN الحقيقي، ولم تُقرأ بياناتها التجارية الحية لهذه المرحلة.

المكوّن مكتبة داخلية اختيارية، وليس مهمة إنتاج أو أداة MCP مسجّلة. لا يوجد تشغيل دوري أو موصل مراسلات أو مسار ينفذ اقتراحات تجارية. المصدر الوحيد الذي يمكن أن يمر من bol هو قراءة مستقلة متحققة؛ لا يكفي وجود كلمة VERIFIED إن اختلفت بيانات إعادة القراءة.

## البنية ودورة المعرفة

1. يعيد النظام استخدام سجلات تنفيذ SAM والتحقق المستقل. تُقبل حالياً أربع قدرات مصدر: `bol_get_retailer_information` و`bol_get_order` و`bol_get_inventory` و`google_mcp_get_drive_file_content` لملف تكاليف JSON منظم.
2. تُطابق الشركة المحفوظة في الهدف، وهوية حساب bol المربوطة صراحةً بالشركة، وSKU مع EAN وربط بنود الطلبات. لا تُستنتج هوية المنتج من الاسم أو EAN وحده. تُرفض المطابقات الملتبسة، وتأتي أدلة التحليل الواحد من الهدف نفسه.
3. تُستخرج القيم من حقول JSON محددة، وتُحسب المساهمة بعد التكاليف المتاحة، ثم تُحفظ المدخلات ومراجعها وبصمة التقرير لإعادة حسابه لاحقاً.
4. يولّد محرك قواعد ثلاث عائلات فرضيات: نقص بيانات التكلفة، مراجعة الهامش السلبي، ومراجعة تغطية مخزون FBB المنخفضة. كل فرضية تتضمن مصادرها وخطة قراءة وحدودها؛ تقدير الثقة وصفي لتغطية الأدلة، وليس احتمال نجاح تجاري.
5. يسجّل محرك التجارب نطاق توقع وحداً أدنى للعينة قبل بداية فترة القياس بتوقيت أمستردام. تُقارن فترة لاحقة مستقلة ومساوية في عدد الأيام وبنفس المنتج والحساب والعملة. النتائج: ضمن التوقع، خارج التوقع، أو غير محسومة.
6. يُحفظ درس مولّد من المقارنة في `knowledge_records` كـ`INFERENCE`، وفي سجل تجاري مرتبط بالتجربة، داخل معاملة واحدة. ليس `SOURCE_FACT` أو قرار مالك. يعيد تجميع سياق التخطيط استرجاعه مع مراجع الأدلة والحدود، ويعيد فحص المصادر وحساب التقرير قبل إدخاله في السياق. فشل تحقق لاحق يستبعده من التخطيط، مع إبقاء التاريخ للتدقيق.

عند تعطيل الطبقة، لا تُقرأ جداولها وتُستبعد دروسها الموسومة من سياق التخطيط. فحص `sam_list_knowledge` الأصلي يبقى سجلاً تاريخياً للاستنتاجات، ولا يدّعي إثبات صلاحية أدلتها التجارية الحالية. الاسترجاع يرث المطابقة اللفظية ونافذة 30 يوماً في PR #37؛ لا توجد ذاكرة دلالية جديدة أو تعلّم أوزان نموذج.

## الربحية وما تعنيه الأرقام

كل المبالغ أعداد صحيحة بالسنت وبعملة EUR فقط، وعلى مستوى مجموعة بنود الطلبات والفترة المحددة، لا تكلفة وحدة تُضرب آلياً بكامل المبيعات.

`الإيراد بعد الضريبة والاسترداد = إجمالي المبيعات − ضريبة المبيعات − إجمالي الاستردادات + ضريبة الاستردادات`

`المساهمة حسب التكاليف المتاحة = الإيراد السابق − مجموع بنود التكلفة المثبتة والمخصّصة لهذه المجموعة`

تشمل فئات التكلفة: الشراء، النقل الوارد، الجمارك، العمولة، تنفيذ الطلب، الشحن الخارج، معالجة المرتجعات، التخزين، الإعلان، التغليف، المصاريف العامة، وأخرى. تُقبل إشعارات الدائن السالبة إذا وردت صراحةً. تُرفض معرفات التكلفة المكررة داخل التحليل، والأرقام الكسرية بالسنت أو التي تتجاوز الحساب الآمن.

لكل فئة `COMPLETE` أو `PARTIAL` أو `UNKNOWN`. وجود بيانات جزئية لا يجعل الباقي صفراً. إقرار اكتمال فئة بلا بنود يعني أن المصدر أقرّ صفراً ضمن نطاقه، وليس أن سام تحقّق من جميع فواتير الشركة. `FULLY_COSTED_WITHIN_DECLARED_SCOPE` تعني اكتمال التصنيف والنطاق المعلنين في الملف، **ولا تعني صافي ربح شركة مدققاً**. نتيجة `PARTIAL` لا تسمح بحكم تجربة حاسم، حتى إذا بدت المساهمة موجبة.

الأوامر المفتوحة غير المشحونة لا تتحول إلى إيراد تلقائياً. تُطابق الكميات المشحونة والإلغاءات والمرتجعات مع المجموعة المعلنة؛ ويجب أن يكون كل بند مشحون للمنتج المختار ضمن المجموعة. يُرفض إسقاط بند منه. مخزون FBB لقطة بتاريخ قراءته، وليس وعداً بالمخزون الحالي أو تغطية FBR. لا يُفترض معدل VAT، ولا تصنيف Margin Scheme، ولا قابلية استرداد ضريبة الشراء.

## فصل الشركات والصلاحيات

المهاجرة `00105_commercial_learning.sql` تضيف سجلات الحسابات والصلاحيات والتحليلات والتجارب والدروس، مع RLS بحسب الشركة ومفاتيح مركبة تمنع وصل تجربة بتحليل شركة أخرى. لا تنشئ أي حساب أو تفويض افتراضي. الصلاحيات الداخلية منفصلة: `ANALYZE` و`EXPERIMENT` و`LEARN`؛ وتحتاج الأخيرة تفعيل ذاكرة PR #37 أيضاً.

هوية المستدعي يجب أن تأتي من سياق مصادقة موثوق، لا من النموذج أو الملف. RLS لا يعزل مالك قاعدة البيانات أو superuser، ولا يعوّض ضبط صلاحيات دور التطبيق ومنع تعديل جداول التفويض. اختبار دور غير مالك أثبت عزل القراءة وعدم قدرته على منح نفسه صلاحية. لا يُدّعى إثبات عزل مفاتيح bol بين الشركات بمجرد تطابق بيانات الهدف؛ هذا بوابة قبول للربط الحي.

لا تحوي المكتبة عميلاً لمزود أو متصفحاً أو منفذ أسعار/مخزون/شراء/بريد. التجارب `OBSERVATION_ONLY` حصراً، وأي وضع آخر مرفوض. لا يعادل حفظ تجربة أو فرضية تفويضاً لأي إجراء خارجي. محتوى الملفات بيانات غير موثوقة؛ لا يُنفّذ كنص أو تعليمات.

اجتاز `git diff --check`، وطبقت الاختبارات جميع المهاجرات المحلية بالترتيب، بما فيها المهاجرة الجديدة. لم تُشغّل GitHub Actions أو قاعدة إنتاج لهذا الإثبات.

توجد الاختبارات في `tests/commercial/acceptance.ts`، والنتائج الخام في `commercial-acceptance-tests.txt`، وأمثلة الأدلة في `commercial-acceptance-evidence.json`. الاختبار يستخدم مهاجرات المستودع الفعلية داخل PGlite مع UUID المدمج بدلاً من امتداد pgcrypto؛ وليس PostgreSQL متعددة العمليات.

- قراءة HTTP محلية فعلية مع إعادة قراءة مستقلة: 8 طلبات GET، وصفر كتابة، ثم حساب وحفظ تقرير ببصمات ومراجع التنفيذ.
- المثال المصطنع: إيراد بعد الضريبة والاستردادات €80.00، تكاليف متاحة €71.00، مساهمة €9.00. هذه أرقام اختبار فقط.
- حالات التكاليف الناقصة، إشعار الدائن، الهامش السلبي، التكرار، الاستردادات، الكسور، تجاوز حدود الحساب، وفشل ربط المنتج والطلب.
- فصل الشركات والحسابات والصلاحيات، ورفض مصدر كتابة أو تحقق فاشل أو إعادة قراءة مختلفة أو ربط خطة غير مطابق.
- منع توقع بأثر رجعي، وتعديل التوقع، ووضع تجربة يغيّر الأسعار، ونتيجة تتبع فترة أو منتجاً مختلفاً.
- دورة مقارنة لاحقة ضمن التوقع وخارجه وغير محسومة؛ وعدم تحويل نتيجة سيئة إلى درس نجاح.
- التراجع عن حفظ الذاكرة إذا فشل سجل الدرس، ومنع تكرار الدرس والتجربة.
- إغلاق تخزين PGlite وإعادة فتحه، وتجميع سياق PR #37 لمهمة مستقلة مع الأدلة، ثم استبعاد الدرس عند إبطال التحقق.

**تقويم التجربة مصطنع**: يُحاكي الاختبار مرور أسبوع تجاري عبر قراءة ساعة اختبار محلية؛ لم ننتظر أسبوعاً ولم ننفذ تجربة سوق فعلية. إغلاق التخزين وإعادة فتحه لا يثبت إعادة تشغيل خدمة أو نموذج حي. الطلبات HTTP تصل لخادم fixtures محلي، لا bol أو Google الحقيقيين. الأدلة التجارية الخام والعملاء لا تُنسخ إلى التقرير المنشور.

## بوابات ما قبل الدمج والتفعيل

1. إغلاق جولة الثبات ومراجعة نتيجتها أولاً، ثم مراجعة PR #37 وهذه المسودة، دون دمج آلي.
2. اعتماد عقد هوية الحساب ومصادر التكلفة وتخصيصها ومراجعتها محاسبياً، بما يشمل VAT والمرتجعات والإعلانات والمصاريف العامة. عدم استخدام أسعار شراء قديمة أو VAT مجهول كتكلفة مؤكدة.
3. تشغيل المهاجرات والأعلام والصلاحيات في بيئة تجريبية فقط أولاً، مع دور قاعدة محدود؛ وإثبات التزامن وإعادة المحاولة على PostgreSQL فعلية. التزامن في أول إنشاء بنفس مفتاح التجربة محمي بقيد uniqueness، لكن أحد الطلبين قد يحتاج إعادة محاولة بعد تعارض؛ لم تُختبر منافسة عمليات مستقلة.
4. ربط الدوال بهوية تطبيق موثوقة وبقدرة تحليل داخل SAM، وتقييد أحجام التقارير وزمن تجميع السياق بعد توسع البيانات. الاسترجاع الحالي يعيد الحساب للتثبت وقد يصبح مكلفاً عند كثرة الدروس.
5. اختبار نموذج حي واسترجاع مستقل بعد إعادة تشغيل خدمة تجريبية، وإثبات صفراً من كتابات المزود، ثم رصد فترات تجارية حقيقية ومراجعة صلاحية الفرضيات.
6. إضافة مصادر السوق/المنافسين وتقييم توقعات معاير عند الحاجة. تظل أي تجربة تغيّر السعر أو الإعلان أو الشراء أو المراسلات مشروع صلاحيات وقبول منفصلاً.

لا توجد مطالبة بأن سام تعلّم تجارة QNAN فعلياً، أو أثبت زيادة الربح، أو صار مخولاً بإدارة البيع والشراء. التسليم يثبت عقود الحساب والأدلة والمقارنة والذاكرة محلياً، ويحدد بوضوح ما لم يُثبت بعد.
