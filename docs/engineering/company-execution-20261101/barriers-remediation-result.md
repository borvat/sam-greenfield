# SAM — إصلاح عائق الرجوع وتقدم الموظفين والمكتب

1 نوفمبر2026 — **إصلاح المصدر مثبت، والنشر الإنتاجي ما زال غير آمن لغياب إثبات النسخ والاستعادة.**

## ما تم إصلاحه

### مسار الرجوع وخطأ42P10

أُنشئ مرشحان minimal من النسخ المنشورة الأصلية، دون تغيير الإصدار الأمامي الموافق عليه8a08e61:

كل مرشح يغير سطرَي SQL فقط في hermesSourceFollowup.ts:

- `ON CONFLICT DO NOTHING` يعمل مع قيد ما قبل00106 ومع القيد الثلاثي بعده.
- إعادة القراءة تختار revision1 صراحة عبر JSON projection دون الإشارة إلى عمود غير موجود قبل migration، ثم تفرض نفس مقارنة report_hash الأصلية.

لم يتغير tenant/source binding أو التحقق المستقل أو hashes أو بوابات Hermes، ولم نحذف أو نعدل أي تقرير أو migration. تبقى revision2 محفوظة. النسخ القديمة غير المصححة تبقى غير صالحة لهذا الرجوع؛ لا تستخدمها بعد00106.

### الموظفون والمكتب على فرع التطوير

- أوصاف عربية عملية للأدوار15، مسؤوليات وقوائم قبول وبروتوكول تسليم وتصعيد. لا نسخ للـcapability owners ولا رفع للتوازي/الصلاحيات.
- مكتب داخل Command Center القائم يقرأ API مصادقاً مرتبطاً بالشركة، ويعرض المهمة والتنفيذ والتحقق والنتيجة والأخطاء والـlease وحداثة البيانات، مع فتح timeline القائم.
- تكلفة منسوبة صراحة إلى model ledger أو UNKNOWN؛ الأرقام sums جزئية من calls المربوطة، وليست فاتورة مزود ولا إجمالي تكلفة موظف/شركة. لا نختلق تكلفة0.
- ذاكرة وأداء scoped؛ لا ترقية مع نقص تكلفة/امتثال مثبت. الملفات الوظيفية ليست إثباتاً أن التكاملات الـ15 تعمل حياً.
- مسودات المهارات تبقى quarantine حتى المراجعة والاعتماد؛ adoption لا ينفذ كوداً خارجياً.
- أصلحت المراجعة مشكلتين فعليتين: SQL NULL كان يسمح بمرور checks ناقصة، وملصق مهمة كان يبقى يعمل بعد تقادم لقطة الواجهة. أضيفت regressions أثبتت الفشل قبل الإصلاح والنجاح بعده.

كل الأعلام تبقى مطفأة، ولا نشر ولا main merge أو قاعدة/خدمة موازية. المراحل الدورية لا تزال غير مفعلة.

## النسخ الاحتياطي والاستعادة: ما بقي محجوباً بدقة

لم أكتفِ ببيانات plan العامة: فُتحت صفحة Recovery لقاعدة Render الحالية. انتقلت إلى تسجيل الدخول، ولا توجد جلسة Dashboard مصادق عليها. عُرض طلب المصادقة الآمن؛ أعاد declined، ولم تُقرأ بيانات اعتماد أو تُكرر المحاولة.

لذلك لم تتوفر قائمة exports حديثة فعلية، أو نسخة مكتملة قابلة للوصول، أو بيئة استعادة معتمدة يمكن إثباتها بلا تكلفة جديدة. لم نُنشئ PITR instance أو خدمة مدفوعة ولم ننقل بيانات العملاء. لا نزعم أن backup غير موجودة؛ الموجود غير قابل للتحقق بصلاحياتنا الحالية.

الاستئناف الآمن بلا خدمات مدفوعة:

1. الوصول المصادق الحالي إلى Recovery لفحص export حديثة مكتملة ونافذة recovery. هذه قراءة لا تحتاج إنشاء خدمة.
2. إذا توفرت نسخة كاملة، إثبات استعادتها في PostgreSQL خاص معزول **موجود ومعتمد**، دون تشغيل تطبيقات أو مزودين عليه ودون طباعة سجلات العملاء؛ التحقق يكون بالبنية والعدادات والـhashs.
3. إذا لم توجد هذه البيئة أو ظهرت تكلفة، نتوقف عند ذلك الشرط. لا ننشئ instance من تلقاء أنفسنا ولا نستعيد في الإنتاج أو مشروع آخر، ولا نخفف RLS للحصول على dump مفلتر وتسميته كاملاً.

## هل أصبح النشر آمناً؟

**لا بعد.** عولج42P10 على مستوى المصدر وSQL المعزول، لكن بوابة النسخة الحالية القابلة للاستعادة وnative/service rollback admission لم تتحقق. مرشحا الرجوع لم يختبرا على خدمات حية، والإصدار الأمامي لم ينشر.

الموافقة المشروطة السابقة محفوظة. بعد استيفاء البوابات تُستخدم ضمن حدودها:00106 فقط عند الحاجة، وexact8a08e61 للخدمات الثلاث، ثم استعادة الهدف المتعطل وإثبات هدف متعدد التخصصات واستمرار آمن. لا طلب لموافقة عامة جديدة، ولا خلط بين نجاح كود المكتب وبين نجاح تشغيل الشركة.
