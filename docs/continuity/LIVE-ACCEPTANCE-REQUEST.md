# Live acceptance preparation template

Status: NOT ACTIVATED. This document is not authority, a signature or a permit.

Before any live execution, bind one reviewed application commit, source/corpus hashes, capability contracts, synthetic tenant/principal, trusted owner public key, exact provider/model/HTTPS endpoint/prices and database-derived expiry. Runtime-created trial and goal identifiers must be real, not invented placeholders submitted as authorization.

Use the existing protocol's elapsed-time, child-goal, call, token, tool and cost ceilings. A per-trial ceiling is not approval for additional trials. Owner-approved aggregate budget and scope must be concrete before spending. Preserve charged or uncertain reservations and the exact rollback snapshot.

The current protocol enrolls three child goals per trial; it cannot establish a ten-case series with one trial. Freeze all ten objectives and one candidate before starting. A code change requires a new series. Frozen-source reasoning and real-source integration must remain separate evidence categories.

For each case retain objective, plan, tool selection, execution, verification, report, specialist contributions, timestamps, usage and cost basis. Actual billed cost must remain unknown when unavailable. Scripted model decisions do not establish autonomous reasoning. No question-specific solver is permitted.

Do not create or promote an untrusted signing identity, bypass the disabled interlock, expand database networking, export secrets, or treat an assistant-side connector as an agent capability to make acceptance appear available.
