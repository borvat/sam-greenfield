## Signing custody and approval delivery

Concrete default if no organizational signer exists: the owner designates a human custodian on their existing workstation and approves creation of one trial-only Ed25519 key. Store its PKCS#8 private key encrypted with a passphrase, local directory 0700/file 0600, outside synchronized folders; unlock locally into the signer process for this run only. Do not reuse SSH/OAuth keys. No private key is uploaded to Render. The owner authenticates the SHA-256 fingerprint of the public SPKI key through the same trusted approval channel before launch; the operator records custodian, fingerprint, approved manifest and deletion/revocation policy. Fixture keys are forbidden.

The local signer signs exactly stableStringify(payload), using Ed25519 and base64 signature, after trial INSERT supplies its actual ID/deadline. Bind kind SAM_LIVE_EVALUATION_APPROVAL, trial/root/company IDs, specHash, release commit, corpusHash, endpoint, positive prices and expiresAt. Its signing policy must compare the preapproved manifest and caps, not sign arbitrary JSON. The same custody may sign the final evidence trace under its separate trace format; retain public verification material after destroying the private key.

Deliver only two service-local files with individual Render API PUTs:

- `/v1/services/{runtimeId}/secret-files/sam-eval-owner-public.pem`, body `{content: publicPem}`.
- `/v1/services/{runtimeId}/secret-files/sam-eval-approval.json`, body `{content: signedEnvelopeJson}`.

Set SAM_EVALUATION_OWNER_PUBLIC_KEY_PATH=/etc/secrets/sam-eval-owner-public.pem and SAM_EVALUATION_APPROVAL_PATH=/etc/secrets/sam-eval-approval.json. Keep the public-key fingerprint pinned in the operator manifest independently of the approval file. Those are authorization material, not private keys; restrict service configuration administration accordingly. Never use the bulk secret-file replacement endpoint because it deletes omitted files. Do not change environment groups.

Render API access: reuse an already authorized operator-local API credential if one exists; none is established here. Otherwise creation of a short-lived-in-practice Render API key, retained only in the custodian's local secret store and revoked after restoration, must be explicitly approved. Do not assume it is technically service-scoped: treat its account authority as sensitive and constrain the executor to the pinned service ID. The existing browser can perform individual Dashboard operations without a new API key, but it does not supply reliable automated create/sign/deliver/restart orchestration within 300 seconds. That manual path is not the recommended binding.
